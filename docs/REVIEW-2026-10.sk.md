# Revízia korodexios-core (október 2026)

Nezávislá revízia jadra `korodexios-core` v0.3.2: bezpečnosť, funkčnosť, architektúra a
vhodnosť ako univerzálneho modulárneho základu pre ďalšie projekty. Dokument popisuje, čo
som overil, čo som našiel, čo som opravil a čo odporúčam ďalej.

## 1. Zhrnutie

Jadro je v dobrom stave a je navrhnuté poctivo: mikrokernel s čistou hranicou medzi
jadrom a modulmi, deklaratívne kontrakty (CLI, konfigurácia, IPC routy, statické mounty,
diagnostika), striktné typovanie (`mypy --strict`), ~550 testov a pokrytie ako "ratchet".
Ako základ pre budúce projekty je vhodné.

Našiel som **jednu vážnu bezpečnostnú chybu** (anonymné spúšťanie príkazov pri
`auth: false`), niekoľko menších slabín na control plane a jednu funkčnú medzeru (RPC
nevracalo výstup príkazu). Všetko je opravené a pokryté testami. Navyše pribudlo
**webové GUI** (`kdx ui`) postavené ako bežný modul.

## 3. Bezpečnostné nálezy

### 3.1 VYSOKÁ - `auth: false` otváralo spúšťanie príkazov (opravené)

`--no-auth` / `core.ipc.auth: false` je zdokumentované ako "anonymné čítanie stavu".
V skutočnosti vypínalo token aj na `POST /api/v1/rpc` a `POST /api/v1/reload`. RPC spúšťa
príkazy modulov s argumentmi od volajúceho. Overil som to naživo:

```text
POST /api/v1/rpc  (bez tokenu, Content-Type: text/plain)
{"command": "backup run", "args": {"source": "<ľubovoľný priečinok>", "dest": "<ľubovoľný cieľ>"}}
-> {"ok": true, ...}   a súbory sa skopírovali
```

Dôsledky: na LAN (`--ipc-host 0.0.0.0`) mohol ktokoľvek v sieti kopírovať súbory, ktoré
daemon vie čítať. Aj na loopbacku mohla **ľubovoľná webová stránka** otvorená v prehliadači
poslať tento "simple" POST (text/plain neposiela CORS preflight a server telo dekódoval bez
ohľadu na typ).

**Oprava:** `requires_token()` - RPC a reload vyžadujú token vždy; `auth: false` otvára
iba `GET /api/v1/status`. Testy: `tests/test_ipc_hardening.py`.

### 3.2 STREDNÁ - chýbala ochrana pred prehliadačom (opravené)

Žiadna kontrola `Origin` ani `Host`. To umožňovalo CSRF (pozri vyššie) a DNS rebinding
(cudzia doména preklopená na `127.0.0.1` číta odpovede ako "svoj" origin).

**Oprava:** `IpcServer.cross_origin_refusal()`: požiadavka s `Origin`, ktorý nie je vlastný
origin daemonu, dostane `403`; na loopback binde aj `Host`, ktorý nie je loopback meno.
CLI, curl ani Docker healthcheck tieto hlavičky neposielajú, takže sa ich to netýka.

### 3.3 NÍZKA - prázdny token vyhovel prázdnej hlavičke (opravené)

`hmac.compare_digest("", "")` je `True`. Daemon s prázdnym tokenom by pustil každého, kto
token nepošle. Chassis síce prázdny token nahrádza náhodným, ale knižničné API
(`IpcOptions(token="")`) to dovolilo. **Oprava:** prázdny token nevyhovie ničomu.

### 3.4 NÍZKA - slowloris (opravené)

Každé spojenie má vlastné vlákno a socket nemal timeout - klient, ktorý nedokončí
požiadavku, blokoval vlákno navždy. **Oprava:** `REQUEST_TIMEOUT_SECONDS = 30` na čítanie
a zápis socketu (nie na beh príkazu).

### 3.5 Vedomé riziká a ich stav

- **HTTP bez TLS** - *vyriešené v druhom kole.* `kdx tls init` vytvorí certifikát,
  `kdx run --tls` servíruje HTTPS (pozri časť 8). Bez `--tls` ide token na LAN stále
  v čistom texte - na vzdialený prístup teda použi `--tls`, VPN alebo SSH tunel.
- **`var/chassis.ipc` na Windowse** - *vyriešené v druhom kole.* Súbor s tokenom aj TLS kľúč
  majú ACL iba pre aktuálny účet (`icacls`), nastavené ešte pred premenovaním na finálny
  názov.
- **Moduly sú kód.** Kto môže zapisovať do `modules/`, `--modules-dir` alebo `kdx.yml`,
  môže spustiť kód s právami daemonu. Je to zámer (pluginy), nie diera.
- **Token = plná dôvera** - *zmiernené v druhom kole.* Modul môže príkaz označiť
  `remote=False` (cez sieť sa nedá spustiť vôbec) alebo `danger=True` (GUI sa pýta).
  Držiteľ tokenu stále spustí všetko ostatné; viac používateľov s rôznymi právami by
  vyžadovalo roly - jeden token = jeden operátor.
- **Chybové hlásenia** modulových rout (`500`) obsahujú text výnimky - vidí ho však len
  autentifikovaný klient.

## 5. Nové: webová konzola (`kdx ui`)

Postavená ako bežný vstavaný modul `modules/web_console/`, nie ako súčasť jadra - jadro
ostáva headless, GUI je ďalší tenký klient vedľa CLI.

```bash
kdx ui                # otvorí konzolu bežiaceho daemonu; ak nebeží, naštartuje ho
kdx ui --no-browser   # iba vypíše URL (server bez GUI, SSH)
```

Čo vie:

- **Overview** - moduly a ich stav, plánované úlohy, pamäť, control plane.
- **Commands** - každý príkaz každého modulu ako formulár. Formulár sa generuje
  z deklarácií `CliArgument`, takže **nový modul nepotrebuje žiadny GUI kód**. Pod
  formulárom je náhľad presného príkazu (`kdx backup plan --exclude ...`) a výstup je ten
  istý text, ktorý by vypísal terminál.
- **Logs** - posledných N riadkov, filter, režim follow.
- **Config** - všetky kľúče s pôvodom (CLI / env / súbor / default), tajné maskované.
- **Diagnostics** - výsledky `kdx doctor`.
- Tlačidlá **Reload config** a **Stop daemon**.

Bezpečnosť GUI: statické súbory neobsahujú nič tajné; všetky dáta idú cez API s tokenom.
`kdx ui` dá token do fragmentu URL (`#token=...`), ktorý prehliadač nikdy nepošle na
server ani do logu; stránka ho presunie do `sessionStorage` a z adresného riadku ho zmaže.
Prísna Content-Security-Policy, žiadne CDN (funguje offline), všetky hodnoty z daemonu sa
zapisujú cez `textContent` (žiadne XSS). Žiadna nová Python závislosť.

## 6. Architektúra - hodnotenie a odporúčania

Silné stránky, ktoré treba zachovať:

- **Deklaratívne kontrakty.** Modul vyhlási príkazy, konfiguráciu, routy a diagnostiku;
  jadro ich spracuje. Preto mohlo GUI vzniknúť bez zmeny jediného existujúceho modulu.
- **Poradie konfigurácie** (CLI > env > local > súbor > default) s provenance.
- **Disciplína pri shutdowne** a jasné exit kódy.
- **Zmrazené API `v2`** - pridávanie je aditívne.

Odporúčania z prvého kola a ich stav:

1. **Oprávnenia na úrovni príkazov** - *hotové* (`remote`, `danger`).
2. **Živé udalosti pre GUI** - *hotové* (`GET /api/v1/ui/events`, záložka Events).
3. **Voliteľné TLS** - *hotové* (`kdx tls init`, `--tls`, `--tls-ca`).
4. **Úlohy na pozadí** - *hotové* (`"background": true`, `GET /api/v1/jobs`).
5. **TUI** - *zámerne nerobené.* Textual je nová závislosť a pravidlo projektu "stdlib
   first" ju nepúšťa bez dobrého dôvodu; webová konzola pokrýva rovnakú potrebu a
   `kdx wizard` ostáva pre terminál. Ak TUI raz bude, má čítať `GET /api/v1/ui/catalog`.

Čo ešte ostáva otvorené:

- **Zrušenie bežiacej úlohy.** Python nevie zastaviť vlákno zvonka; príkaz, ktorý má byť
  prerušiteľný, patrí do plánovača (`context.schedule`) s vlastnou kontrolou zastavenia.
- **Viac používateľov / rolí.** Jeden token = jeden operátor.
- **`kdx tls init` potrebuje openssl.** Bez neho vypíše presný príkaz na spustenie.

## 8. Druhé kolo: bezpečnosť bez komplikácií

Cieľ: čo najbezpečnejšie, ale pre používateľa čo najjednoduchšie - nič nové sa nemusí
nastavovať, kým to nepotrebuješ.

| Funkcia | Ako sa používa | Prečo |
| --- | --- | --- |
| Oprávnenia príkazov | modul pridá `remote=False` alebo `danger=True` do `CliCommand` | interaktívny sprievodca sa nedá spustiť cez sieť; zápisové príkazy chcú potvrdenie |
| Úlohy na pozadí | GUI to robí samo; API: `"background": true` | dlhá záloha nedrží HTTP spojenie a výstup vidno priebežne |
| Živé udalosti | záložka **Events** v `kdx ui` | vidno, čo jadro robí, bez obnovovania |
| HTTPS | `kdx tls init` → `kdx run --tls` | token na LAN nejde v čistom texte |
| Súkromné súbory na Windowse | automaticky | token a kľúč číta iba tvoj účet |
| Potvrdzovanie v GUI | druhé kliknutie na červené tlačidlo | žiadne blokujúce dialógy, žiadne náhodné zastavenie daemonu |

Overené v reálnom prehliadači: formulár s argumentmi (`backup plan --exclude docs
--exclude tests --max-size 1GB`) → úloha `job-1` → výstup; `backup configure` zobrazené ako
"terminal" s vypnutým tlačidlom; `backup run` po prvom kliknutí čaká na potvrdenie; Events
ukazujú `core.job.started/finished`; Stop daemon po dvoch kliknutiach daemon zastaví.
Naživo cez HTTPS: `kdx status`, `kdx --remote`, úlohy, udalosti; obyčajné HTTP na HTTPS
porte je odmietnuté bez pádu.

**Nekompatibilná zmena:** kto spoliehal na anonymné RPC alebo reload pri `auth: false`,
musí po novom poslať `X-Kdx-Token`. Je to zámerné - pôvodné správanie bola diera.

## 9. Tretie kolo: tím, terminál na prvom mieste, služba (v0.4.0)

Zásada od vlastníka: **terminál je hlavné rozhranie, GUI je len nadstavba.** Všetko, čo
vie webová konzola, vie aj `kdx`.

| Oblasť | Terminál | Poznámka |
| --- | --- | --- |
| Používatelia a roly | `kdx users add/list/role/rotate/remove` | `viewer` < `operator` < `admin`; tokeny iba ako SHA-256 hash v `data/users.json` |
| Audit | `kdx audit [--user] [--action] [--json]` | každý príkaz, úloha, reload, stop aj každé zamietnutie; GUI len pre admina |
| Úlohy | `kdx rpc --follow` / `--background`, `kdx jobs list/show/cancel` | zrušenie je kooperatívne; záloha skončí medzi súbormi a nechá čiastočnú kópiu |
| Udalosti | `kdx events [vzor] [--json] [-n N]` | rovnaký živý stream ako záložka Events |
| Zastavenie | `kdx stop` | iba admin |
| Automatický štart | `kdx service install/status/uninstall` | Task Scheduler / systemd / launchd, bez admin práv, `--print` nič nemení |

Opravené chyby nájdené pri tejto práci:

- `kdx rpc ... -- --source C:/cesta/v1.2` posielal argumenty v názve príkazu a daemon ich
  delil podľa `/` a `.` - každá cesta sa rozbila. Teraz idú argumenty oddelene a doslova.
- Daemon spustený bez konzoly (`pythonw.exe`) by spadol pri prvom výpise; výstup teraz ide
  do `os.devnull`, záznam ostáva v logu.
- `data/users.json` a `data/audit.jsonl` sa nikdy nedostanú do gitu (repo aj projekty z
  `kdx init`).

Overenie: 612 testov, pokrytie 88,2 % aj na Windowse (hranica 88 % je splnená už aj tu).
Naživo: roly a audit cez HTTP, zrušenie zálohy 15 000 súborov po 1 763 kópiách (exit 130),
`kdx events`, `kdx stop`, `kdx service install --print` a `status`. Samotné
`kdx service install` som na tvojom počítači **nespúšťal** - zaregistrovalo by trvalú úlohu
pri prihlásení; testy ho overujú s podstrčeným správcom služieb.
